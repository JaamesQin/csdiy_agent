# MIT 6.S081 第 16 讲：文件系统性能与快速崩溃恢复

> 课程：mit-6.s081-fall-2021 · 版本：fall-2021 · 单元：lecture-16

## 学习目标

- 解释 write-ahead logging 的提交点、home 写入和崩溃恢复不变量。
- 分析异步更新、批处理与事务并发如何改善性能并改变持久化语义。
- 追踪循环日志扫描、序列号、最后有效 commit 与幂等 replay 的恢复过程。
- 比较 journaled data 与 ordered data，并说明块重用、revoke、预留和校验和处理的风险。

## 前置知识

- 文件系统块、inode 与空闲位图：能理解一次操作可能同时修改 inode、目录、位图和数据块，并需保持跨块不变量。
- 缓存与磁盘持久性：知道 RAM 缓存在崩溃后丢失，而课程模型假定磁盘仍可读取。

## 核心概念

### 写前日志与提交点

事务先把修改块写入日志，再写入描述已提交内容的记录；只有完成提交后才允许把修改安装到文件系统 home 位置。崩溃后，恢复程序重放已提交事务并忽略未完成事务，使多步元数据更新表现为全有或全无。

来源：mit-6.s081-f21-lecture-16-material@page:1

### 异步、批处理与并发事务

系统调用先修改缓存并快速返回，日志可定期批量提交。批处理摊薄描述/提交与寻道成本，并吸收对同一块的多次修改；开放、提交、写回和释放阶段可重叠。但崩溃可能遗失最近已返回的调用，要求需要持久保证的应用显式使用 fsync。

来源：mit-6.s081-f21-lecture-16-material@page:2

### 循环日志恢复与事务隔离

恢复从日志超级块记录的最老事务开始，依据 magic、序列号和 commit 找到最后完整事务，按顺序重放。重放可重复执行；事务间还要防止后续系统调用的缓存修改被前一事务错误写入日志，因此关闭/快照边界对一致性很重要。

来源：mit-6.s081-f21-lecture-16-material@page:3

### ordered data 与日志空间安全

ordered data 不把文件内容写入日志，而是在提交相关元数据前先把内容写到 home 位置，避免元数据指向旧数据。块类型改变与重用需要延迟或 revoke 记录；日志空间预留防止尚未写回的旧版本丢失。设备写缓存可能重排写入，事务校验和可帮助恢复判断提交记录与数据是否匹配。

来源：mit-6.s081-f21-lecture-16-material@page:4, mit-6.s081-f21-lecture-16-material@page:5

提交：事件时间线和四个崩溃点结果表。

### practice-02 · analysis

分别解释异步更新、批处理、缓存写吸收和阶段并发为何能提高吞吐；再写出它们带来的一个用户可见持久性风险。

提示：性能理由与 crash semantics 分开写。

提交：四项收益和一项语义风险。

### practice-03 · trace

给定“一个已释放旧区段、两个完整事务、一个部分事务”的循环日志，写出恢复扫描如何用起点、序列号和 commit 找到重放范围。

提示：不需要构造字节格式，只标识事务状态。

### practice-04 · comparison

提示：ordered 模式先写数据 home，再提交元数据。

提示：每项写“不变量—违反后果—来源页”。
