## 1. 测试口径

- 测试者只假设看过产品简介、`/help` 和对应 `/help <capability>`。
- 输入按普通用户习惯编写，不强制 Markdown、课程 ID、practice ID 或精确命令。
- 请求直接进入真实 `CoursePilotAgent.handle()`，使用真实 approved Catalog/StudyKitStore、
  临时画像 SQLite、签名上下文和真实 `deepseek-v4-flash`。
- 所有身份、画像、代码和答案均为合成测试数据。
- 用户视角检查可理解性、相关性、连续性和下一步是否明确；开发者视角检查路由、Artifact、
  TaskPlan、实体校验、证据边界、持久化和模型调用。

## 2. 总体结论

单轮、显式、格式规范的请求多数可用，但零经验用户最常见的三类行为仍会显著失败：

1. 使用“第一门”“这讲”“刚才那题”等自然指代；
2. 直接粘贴单行代码或把背景描述和代码写在同一句；
3. 用“会一点”“感兴趣”“先不学了”等口语陈述画像与纠正。

P0 问题集中在上下文丢失、模型 TaskPlan 过度扩张、代码 Artifact 边界错误和未经验证的课程
画像持久化。它们可能造成答非所问、错误诊断、超长回复、高额模型消耗或错误用户数据。

## 3. 问题记录

### CP-NOVICE-001（P1）：首次使用建议退化为画像表单

**上下文**：用户先发送“你好”，随后查看 `/help`。

**用户输入**

```text
我第一次用，也不知道该选哪个功能，你建议我先做什么？
```

**Agent 回答**

```text
当前没有足够的学习画像。请告诉我你想学习的 CS 方向、已有基础，以及每周可投入的时间。
```

**用户视角问题**

- 没有回答“建议先做什么”，而是直接要求填写画像。
- 新用户仍不知道可以跳过画像、直接问课程、代码或材料。

**开发者视角问题**

- Planner 调用了 DeepSeek 1 次，最终只执行 `profile_analysis`。
- 对 onboarding 请求缺少确定性的引导策略，模型分类结果被直接当成功能选择。

**优化与验收**

- 返回 2–3 个可直接点击或复制的起步选项，并说明画像可选。
- 此请求不得写画像；确定性处理时模型调用应为 0。

### CP-NOVICE-002（P1）：单行 Python 被判定为“未收到代码”

**用户输入**

```text
帮我看看这段程序哪里错了 def add(a,b) return a+b print(add(1,2))
```

**Agent 回答**

```text
### 观察
请粘贴最小相关代码，并在 Markdown 代码围栏中标明语言；若有报错，也请附上完整的编译器、解释器或工具链错误输出。

### 诊断假设
- 目前没有足够信息形成具体假设。

### 验证步骤
- 保留能复现问题的最小输入、期望行为和实际行为。

### 下一次尝试
提供最小代码、输入、期望行为和实际行为。

### 限制
- 未收到可静态分析的代码，未运行任何内容。
- ran_code=false
```

**用户视角问题**

- `/help code` 明确说 Markdown 和语言标签可选，实际回答却再次要求 Markdown，前后矛盾。
- 用户已经给出足以判断缺少冒号和缩进的代码，却被要求重新输入。

**开发者视角问题**

- 单行 Python 只有 `def` 特征时没有达到 `looks_like_code` 的双信号阈值。
- 路由正确进入 `code_tutoring`，但 Artifact 提取为空，仍消耗 1 次能力模型调用。

**优化与验收**

- “明确代码请求 + 单个强语法标记”应允许提取候选 Artifact。
- 保留原文并以低置信语言假设回答；不再要求 Markdown。

### CP-NOVICE-003（P0）：背景中的 Python 污染 C++ 语言识别

**用户输入**

```text
我会Python，想学系统，还想请你看看这个：int main(){std::cout << 1; return 0;}
```

**Agent 回答（关键原文）**

```text
### 观察
你提交的代码是 C++ 代码，但当前课程环境是 Python。Python 解析器无法识别 C++ 语法，并报告了语法错误（例如，中文逗号 '，' 和 'int main' 等）。

### 确定性静态诊断
- invalid character '，' (U+FF0C)（第 1 行，第 9 列）
...
### 下一次尝试
请用 Python 重写你的代码。例如，如果你想输出数字 1，可以写：print(1)。
```

**用户视角问题**

- 明显的 `int main`、`std::cout` 被当作 Python，给出了完全错误的修复方向。
- 用户只说自己会 Python，并没有说代码是 Python，也没有“当前课程环境”。

**开发者视角问题**

- 实际 Artifact 是整句
  `我会Python，想学系统，还想请你看看这个：int main(){...}`，而不是冒号后的代码。
- `_infer_language` 把背景中的 Python 当作显式代码语言；Python AST 随后在中文逗号处报错。
- 模型把错误的确定性诊断进一步解释成不存在的课程环境。

**优化与验收**

- 代码请求中的自然语言前缀与 Artifact 必须分离；背景技能不能参与语言标签判定。
- `std::cout` 与 `int main` 应以 C++ 强特征胜出，并显示“按 C++ 分析”的假设。

### CP-NOVICE-004（P0）：切换到新代码后仍分析上一段 Artifact

**上下文**：上一轮分析了一段 C++。

**用户输入**

```text
换一个，这次是Python：def add(a,b) return a+b
```

**Agent 回答（关键原文）**

```text
### 观察
代码中混用了 C++ 和 Python 语法。第一行是 C++ 的 main 函数...第二行是 Python 的 def 语句...
...
请明确你想用哪种语言。如果是 C++...如果是 Python，请删除 C++ 部分...
```

**用户视角问题**

- 用户明确说“换一个”，回答却把上一轮 C++ 和本轮 Python 合并，制造了不存在的混合代码。

**开发者视角问题**

- 本轮单行 Python 未达到代码阈值，`extract_code` 反向搜索并复用了上一轮 Artifact。
- “换一个/这次是”没有作为 Artifact 替换信号。
- 本轮产生 3 次 provider 调用，仍建立在错误 Artifact 上。

**优化与验收**

- 当前轮存在明确新代码声明时，禁止静默回退到旧 Artifact。
- 新 Artifact 解析失败应针对本轮追问，不能合并历史代码。

好的，我们从计算机科学的基础开始。首先，理解计算机如何工作...

**用户视角问题**

**优化与验收**

- 上下文令牌可保存最近展示的受验证 catalog IDs（只保存身份，不保存答案）。
- “第一门/第二门/这几门”必须先解析到最近列表，再执行课程比较或选择。
- 一个选课追问不得生成代码、材料、练习或未上线复盘任务。

### CP-NOVICE-006（P0）：选择“第一门”返回全部 220 个 StudyKit

**上下文**：Agent 推荐 CS168、CS61C、MIT 6.S081。

**用户输入**

```text
我选第一门。
```

**Agent 回答（完整结构）**

```text
你希望学习哪个方向？例如系统、算法、机器学习、安全、Web 或理论。

---

## 当前可用 StudyKit

- `cambridge-semantics-of-programming-languages-2025-26` / ... / `lecture-01` ...
...
- `ucb-cs61c-spring-2026` / `spring-2026` / `lecture-36`：第 36 讲：The TLB, Full Memory Hierarchy

请指定课程和讲次，例如“查看 MIT 6.7960 第 2 讲的 StudyKit”。
```

该回答实际列出了当前全部在线 StudyKit，而不是选择上一轮第一门。完整逐项回答保存在第二批
原始转录中。

**用户视角问题**

- 回答极长且完全偏离“选择第一门”；零经验用户会误以为必须从内部 ID列表中选择。

**开发者视角问题**

- Planner 错误创建 `course_navigation` 和 `studykit_lookup`。
- 没有解析到课程上下文时，lookup 默认列出全部 ready 文档，放大了上游路由错误。
- 完整对话历史携带这段超长回复进入后续模型请求，第二批仅 5 条旅程就消耗 59,268 tokens。

**优化与验收**

- 无明确课程时禁止在普通对话列出全部 220 项；最多返回课程级摘要或精准追问。
- 为输入、历史和能力输出设置独立长度预算。

### CP-NOVICE-009（P0）：自然练习答案和提示连续性失败

**上下文**：Agent 已给出练习 `ex-1`，并明确说“直接发送你的当前答案即可”。

**用户输入**

```text
我觉得应该先算梯度，然后用梯度更新参数。
```

**Agent 回答**

```text
请说明你想了解的概念，或指定课程学习、练习、选课、学习画像或代码辅导任务。
```

后续输入：

```text
我还是不太懂，再给点提示。
```

回答：

```text
要继续剩余任务，请补充：练习 ex-1 的已知条件和问题。
```

对照组使用“我的答案是：...”时能正确进入反馈，但再输入“再提示一点”后，Agent 回答：

```text
### 本题点评
**最重要的修正**：当前答案未包含任何实质内容，未按要求提供三行比较表和噪声来源说明。
...
```

**用户视角问题**

- 帮助和题面承诺“直接发送答案”，但只有特定短语“我的答案是”才可靠。
- 请求更多提示时，被错误评价为提交了空答案。

**开发者视角问题**

- 有有效 active practice context 时，普通陈述没有优先路由到 feedback。
- hint follow-up 没有恢复上一轮答案，而把“再提示一点”作为新的 current answer。
- Planner 生成未被后端满足的 required context，导致任务 blocked。

**优化与验收**

- active practice 存在时，除明确切换任务外，回答性文本默认进入 feedback。
- “再提示/不懂/继续”只提升 hint level，不覆盖上一轮 current answer。

## 4. 正向结果

- 中文引号中的原始 C++ 示例已能识别为 C++，指出缺少 `#`、`<iostream>` 和 `std::`，并保持

## 5. 建议修复顺序

1. **P0：Artifact 和语言边界**——当前轮优先、前缀剥离、背景技能隔离、替换信号。
2. **P0：上下文引用**——最近课程列表、当前课程/讲次、active practice 与上一答案连续性。
3. **P0：模型计划约束**——确定任务优先、required-context 枚举、禁止无关能力扩张。
4. **P0：课程画像验证**——active course/unit 必须经 Store 校验。
5. **P1：口语画像 canonicalization**——程度修饰、兴趣、否定和纠正。
6. **P1：输出预算与去重**——禁止普通对话列出全部 StudyKit，避免 lookup/material 重复。
7. **P1：能力专属恢复提示**——缺上下文时明确说缺什么，不返回全局兜底文案。
8. **P1：onboarding**——提供可直接开始的选择，而不是只要求填写画像。

每项修复都应把本文件对应输入加入离线回归，并在真实 DeepSeek novice suite 中复测相同旅程。
