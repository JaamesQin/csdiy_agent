# StudyKit 质量校准协议

更新时间：2026-08-11

本协议用于在扩大六门课程批量生成前，比较少量新生成讲次与昨日的 CMU 15-213、UCB CS61B
StudyKit 以及 `data/golden/` 中的人审黄金样例。它是离线 authoring 的人工/agent 审查协议，
不是在线 API 行为，也不是把领域语义硬编码进 Schema 的替代品。

## 校准边界

在用户批准开始生成后，先为六门课程各选至少一讲代表性单元；代表性选择应覆盖不同资料
形态和主题，不能只挑最容易的讲次。样本必须完成 `01`–`05`、确定性验证和可复查的
`review-plan`，再进入比较。校准未通过前，不得推广到其余单元，也不得把当前六门课程
的既有低质量输出标为可交付。

比较基线固定为：

- 昨日 CMU 15-213 和 UCB CS61B 的最终 build，以及其中可追溯到 standard checkpoint
  的代表性新生成单元；
- `data/golden/` 中人审批准的 MIT 6.7960 校准单元。黄金数据只读，不得覆盖或批量生成。

基线用于校准判断和展示具体程度，不得复制其课程事实、题目或答案。

## 每个样本的审查材料

独立审计者必须阅读并记录实际检查范围：

1. 本单元所有 source chunks，以及 `01-evidence-plan.json` 和
   `02-learning-content.json`；
2. `03-practice-flow.json` 中的每一道练习、提示、预期证据和评价标准；
3. 最终 JSON/YAML/Markdown、引用页和风险页；
4. Schema、引用、语义相等性、review-plan 和视觉检查报告。

审计者不能只检查文件存在、题目数量、引用格式或页面是否被渲染。至少一名独立审计者
必须与该单元的作者不同；若同一 Luna medium agent 顺序完成 `01`–`03`，仍然必须由
不同的 Luna xhigh agent 复核全部练习。

## 语义质量判定

每道练习逐项回答以下问题：

- 是否对应 `01`/`02` 中明确的 requirement、concept 或 opportunity，而不是只引用
  单元标题？
- 是否给出材料支持的、学习者可以直接开始求解的具体设置，例如数值、代码、对象状态、
  图/集合、概率条件、算法输入或定理条件？学习者不应被要求先自行发明整道题。
- 是否有可观察、可证伪的预期结果或验证步骤？
- `hint`、`expected_evidence` 和评价标准是否针对同一个具体任务，而不是通用套话？
- 若要求改变条件或讨论边界，是否明确改变了什么、预期如何变化，以及材料是否支持该
  限制；若是教学迁移，是否明确标注为迁移？
- 每个关键事实和最终引用是否落到相关 source chunk/page；是否排除了隐藏文字和无关页？
- 题目是否为新的形成性练习，且没有复制受评作业、考试或解决方案？

### 题目自包含性与概念可迁移性

“增加独立性”不等于禁止使用讲义中的变量、符号、题号背景或示例输入。讲义语境可以
复用，也可以复述必要条件；关键要求是题目本身必须自包含，并且主要检验可迁移的课程
概念，而不是要求学习者记住某道讲义题的特殊答案。

因此，作者和审计者使用以下标准：

- 可以保留讲义中的符号、变量名、算法名称和故事背景，但必须在题面中重新定义所有解题
  所需的信息，包括输入、初始状态、约束、操作、目标和可核验的输出或判断标准。
- 题面不能要求学习者“回看讲义第 f 题/例题/图中状态”才能知道缺失条件；如果某个讲义
  条件是解题必要条件，就把它直接写进题目，并给出对应 source anchor。
- 题目应把材料概念应用到一个可独立求解的实例。优先使用自拟的新输入、改变一个条件、
  新的代码/状态或新的比较对象；若课程内容是证明、定义或严格形式推理，也可以复述必要
  条件后要求学习者完成新的推理步骤，不强行脱离原符号体系。
- 练习可以与讲义示例同主题，甚至可以使用其中的变量；但不能只让学习者抄写、解释或
  重放讲义示例。至少应有一个可观察的判断、推导、预测、调试结果、设计选择或条件变化
  后果，能够显示学习者理解了概念。
- `hint`、`expected_evidence` 和 `evaluation` 必须针对这个自包含任务，而不能隐含依赖
  讲义原题的未复述设定。引用用于证明概念和条件，不替代题面提供必要信息。

独立审计者还要做一次“替换检查”：在不改变所考察概念的前提下替换讲义专有的数字、名字、
故事或示例对象后，题目是否仍然有明确的求解路径和可核验结果。若答案只能通过记忆讲义
某题的特例得到，标记为 `lecture_specific_dependency`；若题目把完整场景设计责任交给
学习者，标记为 `generic_exercise_shell`。两者都是 practice blocker，而不是可以用
Schema、引用数量或题目数量掩盖的格式问题。

以下任一情况即为关键不通过：练习只是“围绕 X 设计一个例子”的空壳；题目无法从给定
设定开始回答；预期结果不可验证；引用与题目无关；或多道题只是改写同一模板。该问题
应回到 prompt/checkpoint 修复，不以新增领域专用验证器掩盖。

## 六课批次后的专项执行

六课批次完成后，先对六门课程的全部 practice 做语义专项扫描，再推广到后续课程。扫描
必须同时报告两类问题：

1. 题目不具体或不自包含：缺少输入、状态、条件、操作、目标或可验证结果；
2. 题目过度依赖讲义特例：变量/题号/示例本身没有问题，但没有复述必要条件，或没有
   检验可迁移概念。

修复时保留原始 checkpoint 和 blocker，优先在 Practice prompt/阶段 checkpoint 中修复；
修复后的每道题重新进行自包含性、概念相关性、条件变化和逐项引用审计。若输入、prompt、
pipeline 或质量模式改变，创建新的 fingerprinted build，不原地覆盖旧 build。只有六课批次
闭合、专项扫描完成、修复后的独立审计通过，并且具体性与 `data/golden/` 及昨日
standard/fast hybrid 代表单元相当，才可把该专项作为后续批次的默认质量门槛。

## 与基线的比较和放行

审计者对每个样本记录 `pass`、`needs_repair` 或 `fail`，并附具体题号、source
anchor 和简短理由。放行到批量生成至少需要：

- 所有 Schema、引用、语义相等性和 review-plan 检查通过；
- 没有关键不通过项；
- 每一道练习都具备具体设置、可观察结果和与内容一致的证据要求；
- 新样本的整体具体性、内容关联、题目可解性、引用准确性和学习者可读性与两类基线
  相似，不得用平均分掩盖单道关键缺陷；
- 独立审计者明确记录实际审阅的页码和练习 ID。

若未达到，暂停推广，保留原始 checkpoint 和审计记录，最多针对问题阶段做一次定向修复，
然后由不同审计者复核。只有复核通过后才继续扩展；不得同时保留 fast 和 standard 的
重复作者化路径来“平均”质量。

当前状态：协议已建立，尚未执行新的代表性样本生成或校准；现有六门课程产物不因本协议
而自动变为合格交付物。

### Practice-only 定向修复执行口径

专项扫描确认的是 item-level blocker，不是整课或整讲自动重做命令。实施时先把 blocker
映射到 `(course_id, unit_id, practice_id)`：没有 blocker 的 unit 原样复用已验证 build，
只在 hash、身份、schema、pipeline、prompt 和上游 chunks 一致时继承其 checkpoint 与审计。

有 blocker 的 unit 由一个作者 agent 检查该 unit 的全部 practice，但只修改确认有问题的题目。
条件遗漏而概念正确时补齐题面中的输入、状态、约束、操作、目标和可观察结果；如果题目只
复现讲义特例，则改数字、对象、状态或条件，必要时重构题目。讲义引用可以连接到概念和
条件证据，但不能替代学习者需要的题面条件。`hint`、`expected_evidence`、`evaluation`
和 source anchor 必须与修复后的题目同步。

Practice-only repair 只允许对 `03-practice-flow` 做一次定向修复；不应为修复 practice
重写 `01-evidence-plan` 或 `02-learning-content`。只有修复发现上游 requirement、概念或
证据本身错误时，才升级为受审计的上游阶段修复。作者可以自查并修复以节约成本，但修复
unit 的最终放行仍需要不同 agent 的最小独立门禁；自查结果不能冒充独立审计。
